# alpha_hackathon_2026: лента инсайтов и карточки влияния

Сервис для руководителей крупных компаний (выручка от 15 млрд руб.). По профилю компании или группы он отбирает новости и аналитику банка, объясняет, как событие повлияет именно на эту компанию, и отделяет позицию банка от выводов модели. Каждая цифра в карточке сверяется с источниками.

Этот файл — точка входа для всей команды. Найдите свою папку в таблице ниже и откройте README внутри неё.

## Видение продукта по мнению Матвея

Матвей строит ML-пайплайн, который превращает поток новостей и аналитику банка в короткие объяснения «что это значит именно для вашей компании». Пайплайн нацелен на то, чтобы руководитель за минуту увидел, какие события его касаются, чем они грозят или что открывают, и мог проверить каждую цифру по источнику.

### Что пайплайн принимает на вход

1. **Данные банка о клиентах.** CSV с обезличенными профилями компаний и групп: отрасль (ОКВЭД), размер, география, продукты банка, внешняя торговля, платёжные связи между компаниями. Из них строится профиль компании.
2. **Аналитика банка.** PDF-отчёты, которые читаются постранично: текстовый слой или модель-зрение (Qwen3-VL), с проверкой страниц и сверкой с OCR. Из них получаются фрагменты с номером страницы и датой.
3. **Новости.** Синтетические фикстуры или RSS. Тексты считаются недоверенными: инструкции из них вырезаются до разбора.
4. **Запрос пользователя.** Идентификатор компании, при желании роль (например, финансовый директор) и уточняющий вопрос по открытой карточке.

### Что пайплайн выдаёт на выходе

1. **Лента компании.** Материалы, отсортированные по релевантности для этой компании, с оценкой от 0 до 1, причинами и счётчиком отсеянного. Тема новости связывается с признаками профиля, учитываются смежные отрасли, свежесть и важность материала.
2. **Карточка влияния события (`InsightCard`).** В ней:
   - что произошло, с опорой на факты из источника;
   - почему это важно именно этой компании, с перечнем использованных полей профиля;
   - риски и возможности, у каждого есть ссылка на источник или явная пометка «вывод модели»;
   - позиция банка: только дословные цитаты аналитики со страницей и датой;
   - отдельный блок «Вывод модели», чтобы не смешивать его с позицией банка;
   - рекомендуемые действия и вопросы аналитику;
   - ограничения и список источников.
3. **Ответ на уточняющий вопрос** по карточке, с теми же проверками цифр.
4. **Трасса каждого запуска:** план агента, вызовы инструментов, повторы, стоимость, версия промпта и модели. На эту трассу привязана обратная связь пользователя («полезно / не полезно» с причиной).

### Принципы, на которых держится идея

- Позиция банка и мнение модели не смешиваются.
- Цифры, цитаты и ссылки проверяет код, а не модель; карточка с непроверяемым утверждением не выходит.
- Агент видит данные одной компании и только читает.
- Всё воспроизводимо: версии промптов, кэш ответов модели, дневной бюджет.
- Дорогая генерация карточки запускается только для пары «компания + новость», которую открыл пользователь; для демо карточки считаются заранее.

Подробности и честные ограничения замеров: [ml/OVERVIEW.md](ml/OVERVIEW.md) и [ml/eval/PROTOCOL.md](ml/eval/PROTOCOL.md).

## Как устроена система

```
Фронтенд  ->  Бэкенд (API, хранение)  ->  ML-слой (ml/)  ->  модели организаторов
   ^                                          |
   +---- лента, карточки, ответы, трассы -----+
```

Сейчас ML-слой уже отдаёт данные по HTTP (FastAPI, порт 8001) и работает в режиме заглушки без ключа к моделям. Бэкенд и фронтенд могут строить свою часть против этого контракта, не дожидаясь настоящих моделей.

## Быстрый старт

```bash
git clone git@github.com:boomchik93/alpha_hackathon_2026.git
cd alpha_hackathon_2026
make venv                      # Python 3.13 и зависимости ML-слоя
cp .env.example .env           # без ключа добавьте строку LLM_MOCK=1
make test                      # тесты ML-слоя, без обращений к API
make serve                     # ML API на http://localhost:8001, документация /docs
```

Для сквозного демо в `var/` должны лежать собранные артефакты (`make build`). Исходные данные кейса (`data/`) и `var/` в репозиторий не входят: их передаёт владелец ML-части.

## Правила безопасности

- Файл `.env` и ключи API в репозиторий не попадают. Проверьте `git status` перед коммитом.
- Общий лимит платных вызовов моделей организаторов: 500 руб. в день на всю команду. Платные прогоны запускайте только с `--max-rub`.
- Данные банка обезличены. Не пытайтесь расшифровывать идентификаторы.
