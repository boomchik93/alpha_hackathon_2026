# product

Продукт и аналитика: что строим, для кого, как поймём, что получилось. Ветка разработки: `product/dev`.

## Что нужно сделать

- Описать пользователей и сценарии: кто открывает ленту, какое решение принимает после карточки.
- Зафиксировать границы первой версии (что входит в демо, что нет) и критерии готовности.
- Определить метрики продукта (польза карточки, доля «не полезно» и причины, время до понимания события) и как их собирать. Обратная связь из интерфейса уже сохраняется в ML-слое (`POST /cards/{id}/feedback`, сводка `GET /feedback/summary`).
- Проверять карточки глазами пользователя: тексты, тон, полноту. Замечания передавать в `ml/`.
- Подготовить презентацию и сценарий демо.

## Что уже есть для работы

- Описание идеи и пайплайна по мнению Матвея: раздел в [корневом README](../README.md).
- Описание ML-части: [`ml/OVERVIEW.md`](../ml/OVERVIEW.md).
- Метрики качества и их ограничения: [`ml/eval/PROTOCOL.md`](../ml/eval/PROTOCOL.md), [`ml/eval/report_v2.md`](../ml/eval/report_v2.md).

## Структура папки

```
product/
  README.md          этот файл
  vision.md          видение, пользователи, сценарии
  requirements.md    границы MVP, критерии готовности
  metrics.md         метрики и способ сбора
  demo/              сценарий и материалы презентации
```

Создавайте файлы по мере необходимости.
