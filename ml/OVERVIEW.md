# alpha-hack: ML-слой для ленты инсайтов и карточек влияния

Сервис для руководителей крупных компаний (выручка от 15 млрд руб.). По профилю компании или группы (ОКВЭД, размер, продукты банка, внешняя торговля, платёжные связи) он отбирает новости и аналитику банка, объясняет, как событие повлияет именно на эту компанию, и отделяет позицию банка от выводов модели. Каждая цифра карточки сверяется с источниками, каждый запуск оставляет трассу.

Подробные спецификации: [ML_SPEC.md](docs/ML_SPEC.md), [ml/README.md](README.md), протокол оценки [ml/eval/PROTOCOL.md](eval/PROTOCOL.md), разбор экспериментов [ml/eval/analysis.md](eval/analysis.md).

## Архитектура

```
CSV банка -> profile/build_profile -> var/profiles.jsonl (профиль, положение в отрасли, платёжные связи)
PDF аналитики -> ingest/pdf_vl (текстовый слой | Qwen3-VL, проверки page_check, сверка с tesseract; запасной ingest/pdf_ocr)
              -> ingest/analytics (фрагменты со страницей и датой) -> retrieval/index (BM25, e5 опционально)
фикстуры | RSS -> ingest/news_fetch -> safety.strip_injections -> ingest/parse_item (Gemma) -> ingest/importance (Gemma)
              -> ingest/dedup -> var/items.jsonl
профиль + материалы -> ranking/ranker (тема -> признак, смежность отраслей, BM25 с замороженной статистикой, свежесть, приор важности) -> лента
agent/orchestrator: plan -> tools (белый список, только своя компания) -> перепланирование по данным (search_news, повторный поиск банка)
                    -> сверка противоречий -> interpret (GLM) -> verifier (правила, цифры, цитаты bank_view) -> retry (до 2) -> InsightCard
```

HTTP-слой: `ml/server.py` (FastAPI), Python-функции для бэкенда: `ml/api.py`. Модели данных: `ml/schemas.py`.

## Требования

- Python 3.13, зависимости из `requirements.lock` (необязательная лемматизация: `requirements-lemma.txt`).
- Системные пакеты `poppler-utils` и `tesseract-ocr` с языком `rus` (только для чтения PDF: `make ocr`, `make vl`).
- Данные кейса в `data/` (CSV в `data/structured`, PDF в `data/analytics`) и собранные артефакты в `var/`.
- Доступ к API организаторов нужен только для настоящих моделей. Без `LLM_BASE_URL` (или с `LLM_MOCK=1`) всё работает на детерминированном моке, тексты карточек помечены `[MOCK]`.

## Запуск локально

```bash
make venv       # Python 3.13 + зависимости
cp .env.example .env   # заполнить LLM_API_KEY; без ключа задайте LLM_MOCK=1
make build      # профили, смежность, фрагменты аналитики, материалы, статистика BM25 -> var/
make test
make serve      # http://localhost:8001, документация /docs
```

Осторожно: `make build`, `make items`, `make chunks`, `make profiles` перезаписывают рабочие файлы в `var/`. Перед пересборкой сделайте `cp -r var var.bak-$(date +%Y%m%d_%H%M)`, а с `LLM_MOCK=1` запускайте только на пустом `var/`: мок заменит разобранные новости заглушками.

Стоимость: `make items` (и `make build`) разбирает новости Gemma; ответы кэшируются в `var/llm_cache/`, поэтому платно только при промахе кэша (новые новости или новая версия промпта `parse_item`). Важность материалов при этом берётся из прежнего `var/items.jsonl`. Оценка важности моделью только явно: `make items-importance` (**платно**, вызов Gemma на материал, ~0,5–1 руб. на текущий корпус).

## Запуск в Docker

```bash
LLM_MOCK=1 docker compose up --build   # без ключа, на моке
docker compose up --build              # реальные модели, ключ в .env
curl localhost:8001/health
```

Контейнер монтирует `./data` (только чтение) и `./var`. Для сквозного сценария в `var/` должны лежать собранные артефакты (`profiles.jsonl`, `analytics_chunks.jsonl`, `items.jsonl`, `bm25_background.json`, `flows.parquet`); сырые CSV (≈70 МБ) в репозиторий не входят. Образ можно собрать с лемматизацией: `docker build --build-arg WITH_LEMMA=1 .`.

## Маршрутизация моделей

Только модели из списка кейса (`ml/llm/router.py: ALLOWED_MODELS`), любые другие клиент не пустит. При сбое основной модели вызов уходит на резервную.

| Задача | Модель | Температура | max_tokens | Резерв |
|---|---|---|---|---|
| `parse_item` разбор новости | gemma (`google/gemma-4-26b-a4b-it`) | 0.0 | 1500 | qwen |
| `importance` важность материала | gemma | 0.0 | 300 | qwen |
| `consistency` сверка противоречий | gemma | 0.0 | 600 | qwen |
| `relevance` оценка релевантности (переранжирование) | gemma | 0.0 | 600 | qwen |
| `interpret` карточка | glm (`z-ai/glm-5.3-flash`) | 0.2 | 2500 | qwen |
| `followup_qa` уточняющий вопрос | glm | 0.2 | 1000 | qwen |
| `channels` каналы влияния (выкл.) | glm | 0.0 | 900 | qwen |
| `claim_verify` проверка утверждений (выкл.) | qwen (`qwen/qwen3.6-35b-a3b`) | 0.0 | 2000 | gemma |
| `eval_judge` судья eval | deepseek (`deepseek/deepseek-v4.1-flash`) | 0.0 | 1200 | нет |
| `eval_judge_2` второй судья | qwen | 0.0 | 1200 | нет |
| `label_a`, `label_b` разметка релевантности | deepseek, qwen | 0.0 | 3000 | нет |
| `page_vl`, `chart_vl` чтение страниц PDF | qwen_vl (`qwen/qwen3-vl-30b-a3b-instruct`) | 0.0 | 4500 / 2500 | нет |

Kimi (`moonshotai/kimi-k2.6`) разрешён, но в пайплайне не используется: примерно в 15 раз дороже DeepSeek.

## Сценарий проверки

Сервис запущен (`make serve` или Docker), в `var/` собраны артефакты.

```bash
# 1. Список компаний и групп (115 компаний, 298 групп выше порога 15 млрд)
curl -s localhost:8001/companies | head -c 600

# 2. Профиль, включая положение в отрасли (market_position)
curl -s localhost:8001/companies/U_1595 | python3 -m json.tool | head -60

# 3. Лента компании: оценка, причины, отсев; entries[].tier — основная лента (main) или блок «может быть интересно» (maybe)
curl -s "localhost:8001/companies/U_1595/feed?limit=5&maybe_limit=3" | python3 -m json.tool

# 4. Карточка влияния события на компанию (при первом запросе ~15 с на реальной модели; роль необязательна)
curl -s "localhost:8001/companies/U_1595/insights/n_2026_09_11_cbr_rate?role=cfo" | python3 -m json.tool

# 5. Уточняющий вопрос по карточке (card_id из ответа шага 4)
curl -s -X POST "localhost:8001/cards/ins_U_1595_n_2026_09_11_cbr_rate_cfo/followup" \
  -H 'Content-Type: application/json' -d '{"question": "Что банк думает о ставке?"}' | python3 -m json.tool

# 6. Трасса запуска: план, вызовы инструментов, повторы, стоимость (trace_id из ответа шага 4)
curl -s localhost:8001/traces/<trace_id> | python3 -m json.tool

# 7. Обратная связь и сводка по версиям промпта
curl -s -X POST localhost:8001/cards/ins_U_1595_n_2026_09_11_cbr_rate_cfo/feedback \
  -H 'Content-Type: application/json' -d '{"rating": "down", "reason": "not_relevant", "comment": "не про нашу отрасль"}'
curl -s localhost:8001/feedback/summary
curl -s localhost:8001/health
```

Ожидаемо: в карточке `bank_view` состоит из дословных цитат аналитики банка со страницей и датой, выводы модели лежат отдельно в `ai_inference`, у каждого риска и действия есть `evidence`, а `meta.verifier_issues` пуст или содержит оставшиеся замечания проверки. В трассе видны `plan`, `tool_call`, `replan` (если данных не хватило), `verify`, `retry`.

## Безопасность

- Инструменты агента только читают (`ml/agent/tools.py`), белый список, вызов чужого `company_id` отклоняется и пишется в трассу. Модель получает профиль одной компании, а не весь CSV.
- Данные банка обезличены. Идентификаторы не расшифровываются, модель не должна определять реальные организации.
- Тексты новостей и аналитики считаются недоверенными: инструкции из них вырезаются (`ml/safety.py`), в промптах данные отделены от правил, утечки в карточку проверяются.
- Цифры карточки, цитаты `bank_view` и ссылки на источники проверяет код, не модель.
- Секреты только в `.env` (в `.gitignore` и `.dockerignore`); ключ не попадает в образ.
- Журнал всех вызовов инструментов и LLM: трассы `var/traces/`, расходы `var/spend.jsonl`. Остановка платных вызовов на 90% дневного лимита.

## Масштабирование

Целевая аудитория узкая (сотни субъектов), но слои рассчитаны на рост:
- профили и фрагменты аналитики считаются офлайн и читаются из `var/`;
- важность материала и разбор новости считаются один раз на материал, а не на пару, и кэшируются на диске (`var/llm_cache/`);
- статистика BM25 ленты заморожена (`var/bm25_background.json`): скор материала не зависит от состава пула, добавление новостей не пересчитывает старые;
- дорогой вызов (карточка) делается только для пары, которую открыл пользователь; для демо предрасчёт `python -m ml.precompute --companies demo --top 3` (≈14 руб. на 30 компаний);
- карта смежности отраслей строится из платежей (`make flows`); на 85 тыс. компаний её надо расширять (например, по таблицам «затраты-выпуск»);
- сервис без состояния, кроме файлов в `var/`: масштабируется репликами на общем томе или с заменой файлового кэша на хранилище.

## Мониторинг

Каждая карточка хранит `trace_id`, версию промпта и модель; обратная связь (`POST /cards/{id}/feedback`) привязана к ним.

Ежедневно:
- расход (`GET /health`: `spent_today_rub`; `var/spend.jsonl`) и доля повторов по трассам (`retries`);
- замечания верификатора, оставшиеся после повторов (`meta.verifier_issues`);
- доля «down» и причины по версии промпта: `GET /feedback/summary`.

Еженедельно:
- судья (`python -m ml.eval.run_eval --set v2 --split dev`) на выборке 30 карточек, ручная проверка 10 из них и сверка с судьёй (`ml/eval/judge_review.py`);
- выгрузка обратной связи: `python -m ml.eval.feedback_export` (кандидаты в разметку релевантности и очередь «wrong_fact» для калибровки судьи);
- после правки промпта `interpret` или смены модели сохранённые карточки перегенерируются при следующем запросе (версия проверяется), предрасчёт для демо нужно повторить.

## Метрики и отчёты

Тестовая разметка v2: 40 компаний и групп (dev 20, test 20), 25 материалов в пуле, пары `human` + `llm_agreed`; протокол и ограничения в [ml/eval/PROTOCOL.md](eval/PROTOCOL.md). Все цифры ниже получены командами из соответствующих отчётов.

Лента ([ranking_report_v2.md](eval/ranking_report_v2.md), бесплатно: `python -m ml.eval.run_eval --ranking-only --set v2`):
- Реальные новости (79 за 16–22.10.2026, `ml/eval/real_news.jsonl`): nDCG@5 0,70 (dev) / 0,62 (holdout), F1 отсева 0,54 / 0,46; прирост к прежним параметрам значимый, подробности в analysis.md, раздел «Реальные новости».
- Синтетика v2: nDCG@5 системы: dev 0,83, test 0,86; F1 отсева dev 86%, test 80% (параметры подобраны на dev). До пересборки профилей (T10) test F1 был 85%: разрыв dev − test по F1 вырос с 2 до 6 п.п., подробности в [analysis.md](eval/analysis.md), раздел «Ревью ветки improve/review-plan».
- Неперсонализированный порядок по средней оценке материала у других компаний даёт nDCG@5 dev 0,84, test 0,97, то есть **не хуже системы**: на этом пуле nDCG@5 в основном меряет общую важность материала (53% дисперсии разметки — материал, 11% — компания). Персонализацию показывает AUC «кому показать материал»: медиана 0,81 (у неперсонализированного порядка 0,50).
- Спорные пары разметки (24% пар test) исключены из основных метрик; при их включении nDCG@5 колеблется 0,79–0,83 (раздел «Чувствительность к спорным парам»).

Карточки ([report_v2.md](eval/report_v2.md), 300 пар, судьи DeepSeek и Qwen, прогон 20261021_124003). **Цифры получены на промпте `interpret@v6`** и старом верификаторе; текущий промпт `interpret@v10` (положение в отрасли, соседние новости, блоки противоречий и роли) и проверка целых чисел на карточках с моделью ещё не замерены:
- схема валидна 100%, без повторов 85%, покрытие источниками 99%, цифры `bank_view` найдены в цитируемых фрагментах 100%, утечек prompt injection 0;
- судья DeepSeek: factual 1,64 из 2, карточек с неподтверждёнными утверждениями 53%. Второй судья (Qwen) почти не отличает карточки, согласие судей κ_w 0,02; ручная калибровка судьи не выполнена;
- стоимость карточки 0,16 руб., латентность p50 / p95 15,5 / 31,2 с.

Честно о границах: разметка v2 вне 9 исходных компаний сделана двумя LLM; все 19 новостей синтетические; настоящий отложенный набор `holdout2` ещё не собран и не оценён.

## Тесты и eval

```bash
make test                                            # pytest, без обращений к API (мок)
python -m ml.eval.run_eval --ranking-only --set v2   # лента, бейзлайны, бесплатно
python -m ml.eval.run_eval --set v2 --split dev --max-rub 60   # карточки с судьёй, ПЛАТНО
python -m ml.eval.compare ...                        # парное сравнение двух прогонов
python -m ml.precompute --dry-run                    # оценка стоимости предрасчёта карточек
```

Платные прогоны всегда с `--max-rub` и после оценки стоимости. Общий лимит 500 руб. в день на всю команду.

## Данные и репозиторий

В репозиторий не входят `data/` (архивы кейса), `var/` (производные артефакты и кэш LLM), `.env` и `*.zip`. Список сторонних компонентов и лицензий: [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

```

  profile/ ingest/ retrieval/     данные, разбор, поиск

  agent/                          оркестратор, инструменты, верификатор, трассы
  llm/                            клиент, маршрутизация, кэш, учёт расходов, мок
  prompts/                        версионированные промпты

```
