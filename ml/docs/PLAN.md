## 2. Что выяснилось и что это меняет

### 2.1 Новостей в архивах нет вообще

Кейс даёт только аналитику банка. Внешние новости команда должна добыть сама (пункт 2 постановки: «парсер для сбора новостей из доступных внешних источников»). Это главная дыра в прежнем плане, где новости считались входом.

Решение, два слоя:
1. **Основной:** парсер RSS и страниц нескольких открытых источников (экономические и отраслевые СМИ, сайт ЦБ). Какие источники реально доступны и разрешены, не проверено, это нужно проверить в первую очередь.
2. **Страховка:** курируемый корпус из 40-80 новостей на даты июль-сентябрь 2026, привязанных к темам аналитики банка (ключевая ставка, инфляция, бензин, ОФЗ, золото, потребление, рынок труда, ВВП). Он нужен для детерминированной демо и для eval, чтобы показ не зависел от того, что отдаст интернет в день защиты. Помечать его как тестовый в README.

«Сейчас» в демо фиксируем на середине сентября 2026 (последние документы датированы 14.09.2026).

### 2.2 Целевая аудитория это узкая группа

Порог кейса: выручка > 15 млрд руб.

- Компаний выше порога: **115** (0,13% базы), из них действующих клиентов (`CL_TYPE = CLIENT`) **102**.
- Групп с суммарной выручкой > 15 млрд и хотя бы одним клиентом: **335**. Кейс разрешает работать с компанией «и/или группой», так что группа это легитимный уровень.
- Выручка в рублях, максимум около 1,06e11.

Следствие: не нужно масштабировать на 85 тысяч компаний. Нужно хорошо работать на 100-300 субъектах и показать, что архитектура масштабируется (критерий 07 только про описание подхода).

Состав 115 крупных компаний: Москва 79, Санкт-Петербург 10. Отрасли: оптовая торговля (неспециализированная 11, топливо 6, пищевые продукты 6, напитки 4, зерно 4, химия 4, фарма 3), строительство и застройка (около 17), автодороги 4, перевозки. Признаки: кредит есть у 49, лизинг у 71, внешняя торговля (ФТС) у 57, депозит у 11, факторинг у 0.

### 2.3 Качество данных: что можно использовать, что нет

| Поле / источник | Состояние | Как использовать |
|---|---|---|
| `AMOUNT_WORKERS_SPARK_GRADATION` | пусто в 99,8% | не использовать, брать `AMOUNT_WORKERS_FNS_GRADATION` |
| `FTS_COUNTRY_NAME` | пусто в 90,2% | пустота, судя по всему, означает «нет внешней торговли» (`FTS_FLAG = 0`), проверить совпадение; страны поставок давать в профиль только при `FTS_FLAG = 1` |
| `ECO_MARK_LABEL` | пусто в 4,9% | значения: Оптимизация, Бизнес в новой реальности, Рождение, Стремительный рост; полезный «стадийный» признак |
| `NEGATIVEMARK` | 0/1, у 57% крупных = 1 | по описанию в кейсе «признак ключевого собственника», смысл неясен; **в текст для LLM без уточнения не подавать** |
| Дубли `SYNTHETIC_U` | 1 идентификатор (`U_428697`) на 11 строках с разными ОКВЭД и мелкой выручкой | шум; брать одну строку или исключить из демо |
| Связи с физлицами | только 37% `SYNTHETIC_U` из файла есть в таблице компаний; у крупных клиентов связей мало (в выборке 11 из 115) | второстепенный признак, не строить на нём логику |
| Платежи | обе стороны есть в таблице компаний лишь в 28% строк; контрагенты крупных клиентов известны в 41% случаев; 27 406 платежей «себе»; выбросы до 1,1e12; периода нет | агрегировать топ-контрагентов, считать по известным только долю, явно писать «данные частичные» |
| `MAINOKVED_CODE` | смешанные форматы (`46.73.3`, `86.21`, `41.2` и `41.20`) | нормализовать, брать иерархию кодов для сопоставления с темами |

Это ровно тот шум, под который нужны требования кейса про неполные и неоднозначные данные. В `CompanyProfile` поле `data_quality` становится обязательным и заполняется автоматически.

### 2.4 Аналитические PDF: что осложняет

- Сканы, текстового слоя нет. OCR уже сделан, но шумный: «1П26» превращается в «1126», «г/г» в «r/r», графики дают мусор. Нужен постпроцессинг (словарь исправлений плюс чистка Gemma), разбиение на фрагменты по заголовкам и сохранение номера страницы и документа для ссылок.
- Если качества tesseract не хватит, для сложных страниц с таблицами можно использовать Qwen3-VL-30B-A3B-Instruct (он разрешён и предназначен для изображений). Это дорого по бюджету, поэтому делать один раз заранее и кэшировать, не на каждый запрос.
- **Сталь 2021 года устарела.** Она не входит в список из приложения 2 кейса (его 8 материалов совпадают с остальными PDF). Скорее всего это ловушка или остаток. Обращаться с ней нужно как со старой: хранить дату публикации, в ранжировании понижать вес по давности, в карточке при использовании писать «материал от 2021 года, может быть неактуален». Это готовая демонстрация «корректной работы с неоднозначными данными».
- В списке кейса есть «Commodities performance», в архиве его нет. Уточнить у организаторов. Пока считаем, что документа нет.
- Самый большой документ, `FI_Strategy_3Q26` (27 стр., около 94 тыс. знаков после OCR): основной кандидат для RAG по долговому рынку.

## 4. Скорректированная архитектура (кратко)

```
data/structured/*.csv --> build_profiles --> profiles.parquet (115 крупных + 335 групп)
                                              + топ-контрагенты из платежей (только известные)

data/analytics/*.pdf  --> OCR (tesseract) --> чистка + чанки --> индекс (BM25 + e5)
                          (Qwen3-VL только для сложных страниц, один раз, в кэш)

RSS / сайты           --> news_fetch (кэш) --\
фикстуры (тест)       ------------------------>--> parse_item (Gemma) --> ParsedItem

ParsedItem x CompanyProfile --> ranker (признаки+e5, затем LLM для топ-N)
      --> orchestrator (plan -> tools -> context -> verify -> retry)
      --> InsightCard (bank_view / ai_inference с источниками, страницей PDF и датой)
      --> API для фронта: лента клиента, карточка, уточняющий вопрос
```

Ссылка на источник для аналитики банка содержит: название документа, дату, номер страницы и цитату. Это закрывает критерий «выводы привязаны к первоисточникам».

## 5. Порядок работ

Первый принцип: сначала сквозной минимальный сценарий на 3 клиентах и 5-10 новостях, потом расширение.

**Этап 0. Блокеры (первым делом, параллельно)**
- Получить у организаторов URL, ключ и формат API LLM, точные имена моделей.
- Проверить, какие источники новостей доступны и можно ли их парсить.
- Задать вопросы из раздела 7.
- Согласовать с командой схемы JSON (`CompanyProfile`, `ParsedItem`, `InsightCard`).

**Этап 1. Данные**
- `build_profiles`: нормализация CSV, ОКВЭД, пропуски, дубль, `data_quality`, агрегаты по группам, топ-контрагенты из платежей. Результат в parquet.
- Выбрать 10-15 демо-клиентов (разные отрасли, регионы, наборы продуктов), включая 2-3 «трудных» (мало данных).
- Проверить OCR-тексты: чистка, чанки, метаданные.

**Этап 2. Поиск и разбор**
- Индекс аналитики (BM25 + e5, сервер эмбеддингов, префиксы `query:` / `passage:`).
- `parse_item` на Gemma, дедупликация, фикстуры новостей.
- Ранжирование: сначала эвристика «тема-признак» (таблица 2.5), потом e5, потом LLM на топ-N.

**Этап 3. Интерпретация**
- `interpret.md` на GLM-5.3-Flash, доведение до эталона на 3 клиентах.
- RAG по аналитике банка, разделение `bank_view` и `ai_inference`.
- Verifier и цикл повторов, трассировка.

**Этап 4. Продукт**
- API и интерфейс (согласовать с фронтом): выбор клиента, лента, карточка, уточняющий вопрос со ссылкой на первоисточник.
- Точка входа на главном экране (критерий 09), живой деплой.

**Этап 5. Качество и сдача**
- Eval-набор и отчёт, замер BM25/e5/гибрид, замер стоимости.
- README, Docker (включая сервер эмбеддингов), lock-файлы, `THIRD_PARTY_NOTICES` (e5, tesseract, источники новостей, фикстуры), описание безопасности, масштабирования и мониторинга.

## 6. Риски

| Риск | Что делать |
|---|---|
| Нет доступа к LLM-ключу вовремя | мок-клиент и фикстуры, схемы не зависят от модели |
| Интернет-новости недоступны или нельзя парсить | курируемый корпус как основной режим демо |
| Шумный OCR искажает цифры в аналитике | чистка, ручная сверка ключевых цифр, показ цитаты со страницей, при необходимости Qwen3-VL точечно |
| Устаревшая сталь 2021 попадёт в вывод как актуальная | метаданные даты, вес по давности, пометка в карточке |
| Бюджет 500 руб. в день на всю команду | кэш, предрасчёт, дешёвая модель для массового, дорогая для топ-N, счётчик расходов |
| Эксперты не смогут поднять e5-сервер | Docker Compose с моделью и запасной путь на CPU |
| Смысл `NEGATIVEMARK` неясен | не использовать без пояснения организаторов |
