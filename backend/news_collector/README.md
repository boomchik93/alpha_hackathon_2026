# Сборщик новостей

Собирает новости из открытых RSS-лент (российских и международных), склеивает дубли в события, расставляет теги
по ключевым словам и отдаёт записи в формате `RawItem`, который читает ML-слой (`ml/ingest/news_fetch.py`).
Данных банка здесь нет, моделей сборщик не вызывает: разбор новости остаётся за `ml/ingest/parse_item` (Gemma через `ml/llm`, с учётом дневного бюджета).

## Запуск

```bash
pip install -r backend/news_collector/requirements.txt
python backend/news_collector/main.py run --once      # один проход: сбор, события, выгрузка
python backend/news_collector/main.py run             # живой режим, пауза --interval 600 сек
python backend/news_collector/main.py run --sources all   # + ленты, не подтверждённые организаторами
python backend/news_collector/main.py status
python -m pytest backend/news_collector/tests          # без сети
```

По умолчанию `--sources core`: только издания, чьи ленты уже используются в проекте (`ml/eval/collect_real.py`).
Остальные включаются явно, их статус описан в [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).

## Что получается (`var/news_collector/`, в `.gitignore`)

| Файл | Содержимое |
|---|---|
| `raw_items.jsonl` | по записи на событие в формате `RawItem` (`id`, `title`, `text`, `published_at` без времени, `publisher`, `url`, `kind`, `fetched_at`). Вход для `parse_item` |
| `news.json` | те же события с источниками, `verification` (`confirmed`: первоисточник или 2+ издания), `tags` и ссылкой `item_id` на `raw_items.jsonl` |
| `taxonomy.json` | расшифровка тегов |
| `news.db` | SQLite: статьи и события, история сбора |

Чтобы ML-слой взял эти записи, скопируйте строки `raw_items.jsonl` в вход `ingest` или подключите файл в `fetch_news()` (сейчас там `fixtures` или `rss`).
Очистка инструкций из текста (`ml/safety.strip_injections`) происходит в ML-слое до разбора: сборщик отдаёт тексты как есть, считайте их недоверенными.

## Как это работает

1. Сбор лент (`collector.py`): недоступный источник логируется и пропускается; старше `MAX_AGE_DAYS` дней не берём; заголовки не на русском или английском отбрасываются.
2. Предфильтр по ключевым словам (`taxonomy.py`): нужна хотя бы одна экономическая тема. Официальные источники проходят всегда.
3. Полный текст страницы через trafilatura (для Google News только заголовок и аннотация).
4. События (`dedup.py`): статьи об одном и том же склеиваются по близости заголовков; русские и английские публикации между собой не склеиваются.
5. Теги по правилам: темы (26), разделы ОКВЭД, регионы РФ, страны (ISO), `affects` (кого касается, привязано к признакам клиента: `borrowers` ↔ `CL_PRODUCT_LOA_MARK`, `foreign_trade_firms` ↔ `FTS_FLAG` и т. д.). Теги грубые: это подсказка для ранжирования, а не разбор.

## Ограничения

- Теги по ключевым словам дают ложные срабатывания; точный разбор (факты, `okved_hints`, регионы) делает `parse_item`.
- Таксономия тем отличается от `ml/topics.py`; соответствие ещё не построено.
- Проверка прав на использование текстов изданий не выполнена (см. THIRD_PARTY_NOTICES).
